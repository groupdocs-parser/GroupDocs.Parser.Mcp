# 26.10.0 — GroupDocs.Parser 26.8.0, metered licensing documented, empty-text fix

## What changed

**`extract_text` no longer answers with nothing.** A document with no text layer (a scan, an
image-only page, a PDF with no content stream) produced an **empty response** once the server was
licensed or metered: the engine returns an empty string rather than a null reader, and the
evaluation banner that used to fill the response disappears when a licence is in effect. The agent
received a blank answer with no explanation. It now returns a sentence naming the file, saying the
document has no text layer, noting that there is no OCR step, and pointing at `get_document_info`
and `extract_barcodes`. Unlicensed behaviour is unchanged.

This was found by running this product's integration suite for the first time (see below) with
metered keys configured.

**The repository gained a `.dockerignore`.** `docker/Dockerfile` does `COPY . .`, so a local build
shipped the whole working tree — `src/**/bin`, `src/**/obj` and `build_out/`, around 800 MB — and
the context transfer failed before the build started. CI never hit it because a fresh checkout has
none of those. Local builds are how this Docker-only product gets verified before release, so they
have to work.

**Engine bumped to GroupDocs.Parser 26.8.0** (was 26.6.1). Under `net10.0` the engine now resolves
its `GroupDocs.Parser.Net100` runtime sub-package instead of `GroupDocs.Parser.NetStandard21`;
SkiaSharp native assets (Linux, Win32, macOS) and `Microsoft.ML.OnnxRuntime` still come in
transitively, so the image needs no extra native references.

**Metered licensing is now declared and documented.** The capability shipped in 26.9.0 with
`GroupDocs.Mcp.Core` 26.9.0 — `ParserLicenseManager` already implemented it and `get_license_status`
already reported it — but this product's manifest and docs never mentioned it, so a client reading
`server.json` could not discover the variables. This release closes that gap:

- `.mcp/server.json` declares `GROUPDOCS_METERED_PUBLIC_KEY` and `GROUPDOCS_METERED_PRIVATE_KEY`
  (the private key marked `isSecret`), matching every other GroupDocs MCP server.
- `GROUPDOCS_LICENSE_PATH` is described accurately: any GroupDocs licence file, read inside the
  container, ignored when metered keys are set.
- README and `llms.txt` gained the licensing section used across the family: the two modes,
  "metered wins", both keys required, the outbound-connectivity requirement, and how to keep the
  private key out of a committed config.
- README and `llms.txt` now name the tools as the protocol exposes them (`extract_text`, not
  `ExtractText`) and list `get_license_status`, which was missing from both.
- Evaluation limits are now stated concretely instead of "outputs may be size-limited": 1,600
  characters and 20 lines of text per file, 5 pages/sheets/slides, 20 spreadsheet rows, 5 metadata
  properties, 100 files per session. For an extraction product this is the single most important
  thing to know, because the output looks valid and is silently incomplete.

## Why

A customer is evaluating this server with metered licensing. The keys worked, but nothing in the
manifest or the documentation said so, and the evaluation limits were described too vaguely to
explain why unlicensed extraction returns a fraction of a document.

## Verification

Against this build, engine 26.8.0:

- `dotnet build src -c Release` — 0 errors; unit tests 14/14 pass.
- Live MCP session, metered keys set: `get_license_status` returns `"mode": "metered"`,
  `"source": "metered-keys"`, engine `26.8`, with consumption reported.
- `extract_text` with the `fileName`-only form returns the full document text (3,609 characters
  from a 2-page invoice), confirming both the 26.9.0 file-resolution fix and that metered lifts the
  1,600-character evaluation cap.
- `tools/list` reports all seven tools.

## Migration impact

No tool, parameter or response shape changed. Existing `GROUPDOCS_LICENSE_PATH` deployments behave
exactly as before, and setting the two metered variables switches the server to metered licensing
and makes it ignore the licence file.

One response text changed: a licensed `extract_text` on a document with no text layer used to
return an empty string and now returns a sentence explaining why. A caller that tested for "empty
means no text" should test the message instead — and gains the ability to tell "no text in this
document" apart from "the call returned nothing".
